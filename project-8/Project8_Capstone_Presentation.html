Project 1 · Olist delivery-delay prediction

Catch late orders
before dispatch

Joined e-commerce tables and trained a Random Forest using only price, freight, and promised delivery time—features known when the order is placed.

The key lesson was leakage: actual delivery time cannot be used to predict a delay before delivery.

Honest result

0.221
late-class F1 · recall 0.149

The weak recall exposed the limits of a three-feature model and gave a concrete next step: richer logistics history.

1 minute · “I chose early-warning features, then found that a high accuracy score hid poor detection of late orders.”
Project 2 · Customer churn

Turn churn risk into
a retention action

Built a Telco churn pipeline with customer, service, and billing features; compared classification approaches and addressed class imbalance.

Predicted risk is most useful when tied to a decision threshold and a retention action—not treated as a yes/no fact.

What I practiced

  • Feature engineering in a reusable pipeline
  • Stratified validation and precision/recall tradeoffs
  • Thresholds mapped to low, medium, and high risk
1 minute · “The important choice was how to balance missed churners against unnecessary outreach.”
Project 3 · Store-sales forecasting

Forecast demand
through time

Compared tree ensembles, created grouped lags and rolling statistics, then built a chronological out-of-fold stack for sales forecasts.

Every lag must come from the same store/product series and from a date earlier than the prediction date.

Competition handoff

2.04443
Kaggle public score

That score uses a different metric from the local RMSE, so the values should not be compared directly.

1 minute · “Time-aware validation and metric alignment mattered more than a single model score.”
Project 4 · Image classification

Classify images with
transfer learning

Compared a CNN trained from scratch with ResNet18 transfer learning, then fine-tuned the final layer block.

The best reported validation result was 98.34% accuracy and 0.9785 macro-F1.

Best validation run

98.34%
accuracy · ResNet18 fine-tuned

Transfer learning improved the result while keeping the learned representation useful for a smaller dataset.

1 minute · “I learned to compare not just accuracy, but how much of the pretrained network to tune.”
Project 5 · Airline sentiment NLP

Classify reviews
and serve them

Compared a TF-IDF + Linear SVM baseline, fine-tuned DistilBERT, and an external LLM. The deployed API uses the compact SVM and preserves training-time spaCy preprocessing.

FastAPI validates requests; JSON logs and a three-feature drift report support monitoring.

Accuracy vs. footprint

82.22%
SVM accuracy · 0.7673 macro-F1

DistilBERT reached 83.75% accuracy and 0.7868 macro-F1, with a much larger model and runtime.

1 minute · “I selected a smaller model for this CPU deployment and documented the accuracy tradeoff.”
Project 6 · Chest X-ray classification

Apply computer vision
to medical images

Trained image classifiers on the chest X-ray dataset and practiced image loading, preprocessing, training, and evaluation.

This is a learning project: model predictions would need careful validation before any clinical use.

Skills carried forward

  • Image pipelines and batching
  • Model training and evaluation
  • Clear limits for high-impact predictions
1 minute · “I learned that a model score does not establish clinical reliability.”
Project 7 · AI Voice Agent

Handle support requests
through conversation

Built a voice-agent prototype for support and inquiry handling, connecting spoken input with an assistant response and a user-facing interaction flow.

The AFL domain-locked agent was a related experiment in grounded answers, tool use, and guardrails.

What mattered

  • Keep responses grounded in available information
  • Validate tool inputs and handle failures clearly
  • Design the conversation around the user’s task
1 minute · “Agent quality includes safe routing and graceful failure, not just fluent answers.”
Project 8 · Production deployment

Make the model
usable outside a notebook

Packaged Project 5’s sentiment model as a FastAPI service and Docker image. Added input validation, a health check, structured prediction logs, a drift report, automated tests, and GitHub Actions.

The GitHub workflow is green. The API is live on Render and a real prediction returned “positive.”

Reflection · what I would improve

Validate the whole
prediction path

“The hardest recurring problem was making the evaluation match real use: prevent leakage, keep preprocessing identical, choose a useful metric, and test the actual serving artifact.”

Next time

  • Define the prediction moment and metric first
  • Package the exact preprocessing and model together
  • Automate an end-to-end smoke test before deployment

Final note

Strong models matter. Reliable data, honest evaluation, and a clear user workflow make them useful.

1 minute · Close · “I’d start deployment and monitoring earlier so the final result is evaluated as a complete service.”
